## The Definition of Quantum Job

A quantum job in OQTOPUS is a structure consisting of several fields, some of which also include subfields.
This section describes how quantum jobs are structured.

The following fields shows the top-level hierarchy of a job's data structure. Fields labeled as "*user-specified field*" must be specified when submitting the job to the cloud.
The parentheses following each field name indicate the OpenAPI type and format.

- **`job_id (type=string)`**
  The unique identifier for the job. OQTOPUS Cloud assigns this value when the job is submitted.
- **`name (type=string)`**
  The name of the job. *user-specified field*.
- **`description (type=string)`**
  The description of the job. *user-specified field*.
- **`device_id (type=string)`**
  The identifier of the device where the job is executed. *user-specified field*
- **`job_info`**
  Detailed fields related to the job. See [Job Info](#job-info).
- **`transpiler_info`**
  Fields related to the transpiler. See [Transpiler Info](#transpiler-info).
- **`simulator_info`**
  Fields related to the simulator. See [Simulator Info](#simulator-info).
- **`mitigation_info`**
  Fields related to error mitigation. See [Mitigation Info](#mitigation-info).
- **`job_type (type=string)`**
  The type of job. See [Job Type](#job-type).
- **`shots (type=integer)`**
  The number of shots for the job. Must be an integer greater than or equal to 1. *user-specified field*.
- **`status (type=string)`**
  The state of the job. See [Job State Transition](job_state_transition_diagram.md).
- **`execution_time (type=number)`**
  The time in seconds that the job used a QPU or simulator. This value is represented with up to three decimal places.
- **`submitted_at (type=string, format=date-time)`**
  The timestamp when the job was submitted to the cloud. OQTOPUS Cloud assigns this value.
- **`ready_at (type=string, format=date-time)`**
  The timestamp when the backend retrieves the job via the OQTOPUS Cloud Provider API. OQTOPUS Cloud assigns this value.
- **`running_at (type=string, format=date-time)`**
  The timestamp when the job starts execution on a QPU or simulator. OQTOPUS Cloud assigns this value when the backend changes the job's status from `ready` to `running` via the OQTOPUS Cloud Provider API.
- **`ended_at (type=string, format=date-time)`**
  The timestamp when the job's status changes to `succeeded`, `failed`, or `cancelled`. OQTOPUS Cloud assigns this value.

### Job Type

This field represents the type of job. The following types are available:

- **`sampling`**
  A job that executes a single quantum program `shots` times. The execution result indicates how many times each value was observed.
- **`estimation`**
  A job that computes the expectation value by measuring a specified observable on the quantum state created by the quantum program. The execution result is a complex number.
- **`sse`**
  "SSE" stands for "Server-Side Execution". This job type runs the user's program on a backend close to the QPU, exclusively using the QPU.
  It is well-suited for running hybrid classical-quantum algorithms such as QAOA.
  The user can output execution results in any format within the log files generated by their program.
- **`multi_manual`**
  A job that runs multiple quantum program samplings in parallel. The execution result consists of the sampling results for each quantum program.

A job with `job_type=sampling` is called a "sampling job", while a job with `job_type=estimation` is called an "estimation job". Other job types follow the same naming pattern.

### Job Info

`job_info` is a structure that holds data related to the execution of individual quantum jobs.
The fields in `job_info` vary depending on `job_type`. The descriptions for each `job_type` are as follows:

#### **Sampling Job (`job_type=sampling`)**

- **`program`**
  Specifies a quantum program in OpenQASM 3 format as a single-element string array.
  The OpenQASM 3 program must include `measure` statements. *user-specified field*.
- **`transpile_result`**
  The quantum cloud sets this field with the transpilation result.
- **`result`**
  The quantum cloud sets this field with the sampling results.
  Below is an example of a `result` for sampling job. The byte order of the keys in `counts` follows LSB (Least Significant Byte).

```json
"result": {
  "sampling": {
    "counts": {
        "10": 84,
        "11": 387,
        "00": 454,
        "01": 75
    }
  }
}
```

- **`message`**
  The quantum cloud sets this field with a message related to the job execution result.

#### **Estimation Job (`job_type=estimation`)**

- **`program`**
  Specifies a quantum program in OpenQASM 3 format as a single-element string array.
  The OpenQASM 3 program **must not** include `measure` statements. *user-specified field*.
- **`operator`**
  Specifies Pauli operators (**`pauli`**) and their coefficients (**`coeff`**) as an array. *user-specified field*.
  For example, the following JSON represents the operator `(1.0 + 2.0j) * X0 X1 + (3.0 + 4.0j) * Y0 Z1` (where `j` is the imaginary unit):

```json
"operator": [
  {
    "pauli": "X 0 X 1",
    "coeff": [1.0, 2.0]
  },
  {
    "pauli": "Y 0 Z 1",
    "coeff": [3.0, 4.0]
  }
]
```

- **`transpile_result`**
  The quantum cloud sets this field with the transpilation result.
- **`result`**
  The quantum cloud sets this field with the estimation results.
  Below is an example of a `result` where the expectation value is `1.0 + 2.0j` and the standard deviation is `3.0`:

```json
"result": {
  "estimation": {
    "exp_value": [1.0, 2.0],
    "stds": 3.0
  }
}
```

- **`message`**
  The quantum cloud sets this field with a message related to the job execution result.

#### **SSE Job (`job_type=multi_manual`)**

- **`program`**
  Specifies the Python program to be executed on the backend, encoded in Base64 format. *user-specified field*.
- **`result`**
  The quantum cloud sets this field with the result of the last quantum program executed by the SSE job.
- **`message`**
  The quantum cloud sets this field with a message related to the job execution result.

#### **Multi Manual Job (`job_type=multi_manual`)**

- **`program`**
  Specifies quantum programs in OpenQASM 3 format as a string array for parallel execution.
  Ensure that the total number of qubits does not exceed the QPU’s qubit capacity. *user-specified field*.
- **`combined_program`**
  The quantum cloud sets this field with a quantum program that combines multiple programs into one for parallel execution.
- **`transpile_result`**
  The quantum cloud sets this field with the transpilation result of `combined_program`.
- **`result`**
  The quantum cloud sets this field with the results of the multi manual job.
  - `counts` contains the sampling results of `combined_program`.
  - `divided_counts` is obtained by dividing `counts` back into the individual `program` sampling results.
  - The keys of `divided_result` correspond to the array indices ("0", "1", "2", ...).
  - The byte order of the keys in `counts` follows LSB (Least Significant Byte).
  Below is an example of a `result` for a multi manual job:

```json
"result": {
  "sampling": {
    "counts": {
        "10": 84,
        "11": 387,
        "00": 454,
        "01": 75
    },
    "divided_counts": {
      "0": {
        "10": 84,
        "11": 387,
        "00": 454,
        "01": 75
      },
      "1": {
        "10": 84,
        "11": 387,
        "00": 454,
        "01": 75
      }
    }
  }
}
```

- **`message`**
  The quantum cloud sets this field with a message related to the job execution result.

### Transpiler Info

OQTOPUS Cloud assumes that its backend uses [Tranqu Server](https://tranqu-server.readthedocs.io/) for quantum program transpilation.

The `transpiler_info` field consists of the following two subfields:

- **`transpiler_lib (type=string)`**
  *user-specified field*.
- **`transpiler_options (type=string)`**
  *user-specified field*.

For details on each field, refer to the [Tranqu Server Document](https://tranqu-server.readthedocs.io/en/stable/usage/interface_specifications/#message-transpilerequest).

The available values for `transpiler_lib` depend on the version of [Tranqu](https://tranqu.readthedocs.io/stable/) (a transpiler framework) supported by the quantum cloud.

See [Transpiler Library](https://tranqu.readthedocs.io/stable/usage/how_it_works/#built-in-components) for available options.

To use Qiskit with `optimization_level=2`, specify `transpiler_info` as follows:

```json
"transpiler_info": {
  "transpiler_lib": "qiskit",
  "transpiler_options": {"optimization_level": 2}
}
```

#### default transpiler

In the following cases, the quantum cloud uses the default `transpiler_info`.

- When the submitted job does not have the `transpiler_info` field.
- When null is specified for the `transpiler_info` field.

```json
"transpiler_info": null
```

- When an empty JSON object is specified for `transpiler_info`.

```json
"transpiler_info": {}
```

The default uses the following `transpiler_info`.

```json
"transpiler_info": {
  "transpiler_lib": "qiskit",
  "transpiler_options": {"optimization_level": 2}
}
```

When the user uses the default `transpiler_info`, the quantum cloud overwrites it with the `transpiler_info` actually used.

#### Not Using a Transpiler

To disable the transpiler, set `transpiler_lib` to `null`. (not `transpiler_info` to `null`)

```json
"transpiler_info": {
  "transpiler_lib": null
}
```

### Mitigation Info

This section describes the error mitigation information used by the quantum cloud.

- **`readout (type=string)`**
  Specifies the method of readout error mitigation. *user-specified field*.
  Currently, the following method is supported:

```json
"mitigation_info": {
  "readout": "pseudo_inverse"
}
```

By default, error mitigation is **not applied** in the following cases:

- When the submitted job does not have the `mitigation_info` field.
- When null is specified for the `mitigation_info` field.

```json
"mitigation_info": null
```

- When an empty JSON object is specified for `mitigation_info`.

```json
"mitigation_info": {}
```

If the submitted job does not have the `mitigation_info` field, OQTOPUS Cloud converts it to the following:

```json
"mitigation_info": null
```
